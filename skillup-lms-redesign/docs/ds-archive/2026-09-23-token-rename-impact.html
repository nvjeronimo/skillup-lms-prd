What a second rename would cost

If the 47 Material-named roles become element-first names such as text/muted and bg/brand, what moves, what breaks, what has to be rewritten, and how long it takes. Measured on the live files on 22 September 2026.

Applied, 22 Sep

Nelson chose element-first and it went live the same evening, published and accepted in ICP. 83 tokens, not the 53 proposed here: the 47 roles renamed in place, 20 tokens that split a role by element (border/primary, icon/primary, bg/inverse, bg/on-media…) and 16 accents. About 6,000 paints re-bound in the DS and 2,800 in ICP, 0 left, no colour changed. The final names differ from §2 in places: the word is primary, not brand (bg/primary, text/on-primary, bg/primary-soft); surface-container became bg/faint and surface-variant was kept as bg/subtle, not folded (they differ in Light too); on-surface-faint became icon/faint, success-bright icon/success-strong, and primary-outline-variant border/primary-muted. The colour memo §0 holds the final map.

Legacy layer being retired, 23 Sep

The 35 SKO leftover and component tokens and the 69 Untitled UI tokens are gone: DS and ICP verified at 0 before each deletion, snapshot saved. The last group, 146 Untitled UI utility colours, is being re-bound by context rule (container fill → bg/, stroke → border/, text → text/, vector → icon/; hues → neutral, primary, status or one of the four accents) and will be deleted once DS and ICP read 0. Accents are never baked into a component, only pickable (Badge Color=Teal). An interim _Vendor (Untitled UI palette) collection holds the same values during the move and goes with the legacy group. The prototype got tokens/colors.css v4 the same day: 83 --color-* tokens in six modes, --sk-* kept as aliases.

Figma bindings

83% are a rename in place (the variable keeps its id, every binding follows). 10% are roles that serve several elements, above all primary, which is a fill, a border, an icon and a text at once; element-first splits it into four tokens and a script re-binds by node type. Same values, zero pixel change.

Code

Nothing. The prototype still runs the July --sk-* file (45 variables, v3.2, 24 Jul) and never took the Material names. SKO's Storybook repo has not received a first export. Whatever name we export first is the first name developers ever type.

Documents and frames

The real cost. 1 024 mentions in the nine HTML documents, the whole designer manual (47-row cheat sheet, 40-row lookup table, nine images rendered from the library), and 675 mentions in 592 Figma text nodes, most of them the generated Colours boards and the roles appendix.

Consumers

ICP takes renames automatically, as it did on 19 Sep. Its annotations never cite token names (checked on all 39 pages). The Mobile App file binds none of the 47 roles; it is still on the old variables. Other consumer files: unknown, Nelson has the list.

One visible change

Folding surface-variant into bg/subtle changes 716 fills in Dark only (#122228 → the container's Dark). Everything else keeps its value. Keep it as its own token and nothing changes.

Window

The cost is lowest before the first export to code and before the manual is shared. After that, every rename is also a code migration and a retraining.

3What the numbers say

  • 26 917 bindings (83%) follow a rename in place. Same mechanism as 19 Sep: the variable id survives, ICP received the renamed collection without a single re-bind.
  • 3 126 bindings (10%) are re-bound by a rule, all on seven roles that today serve several elements: primary 2 180, info 339, primary-container 244, the three on-*-container borders 356, error 7. The rule is mechanical: fill on a container → bg/, stroke on a container → border/, fill or stroke on a shape → icon/, text → text/. The new tokens alias the same primitives, so no pixel changes.
  • 1 515 bindings (5%) need one decision each, because the library already uses a text colour as a fill or a border colour as an icon: on-surface as a dark fill (420), outline as an icon colour (772), on-primary as a knob fill (179), fixed-white as a white pill (144). Either keep permissive scopes and leave them, or re-bind to bg/inverse, icon/muted, bg/on-media. Element-first makes these misfits visible; Material hid them.
  • 716 bindings (2%) change colour if surface-variant is folded, and only in Dark. Keeping it as bg/subtle-alt costs one token and changes nothing.
  • The Mobile App file is not a consumer of the roles. Its two dev-ready pages bind 1 734 paints to 81 variables, none of them a Model C role. It will need the Model C migration or the element-first one, whichever wins; the rename does not make that worse.
  • Base components were not re-scanned. The 19 Sep count for the whole DS was 180 124 bindings on the roles. Buttons bind primary heavily, so the split script must run there too; the base pages are where the 22 Sep clean-up already moved 18 checkbox marks and 310 overrides, so the tooling exists.

5Risks, from the last migration

  • Same-collection aliases resolve in the default mode unless the modeId is kept; the first Model C run was rolled back for this. The checker rule is written down in the Migration doc.
  • Forced modes are untouched. Renaming variables does not change modes or modeIds, so the 1 317 nodes forcing a mode in the DS and ~735 in ICP stay as they are.
  • Library style edits do not reach nested usage in consumers until the components using them are republished as CHANGED; the focus-ring styles need the same trick again if focus-ring-gap is renamed.
  • Long scans kill the plugin. The Desktop Bridge stopped answering for the DS during this measurement; the official MCP finished the job. Run passes page by page with stored progress.
  • Read descriptions before folding a value (the bg-secondary_alt lesson). Only surface-variant folds here, and its description says “was Background/bg-secondary”, nothing about Dark.
  • Credibility. The team was told “decided, live since 19 Sep”. The honest line is in the Challenge doc: we chose Material for the sync, we measured, the sync never depended on it.

6Decisions needed before step 1

  1. surface-variant: fold into bg/subtle (716 fills change in Dark) or keep as bg/subtle-alt.
  2. icon/ as its own folder or inside text/: 4 tokens either way; a separate folder is clearer in the picker, one folder fewer to explain.
  3. The 1 515 misfits (text colour as fill, border colour as icon): keep permissive scopes, or re-bind to bg/inverse, icon/muted, bg/on-media.
  4. Word choices: subtle / muted / strong for the neutral background ladder, muted / subtle / placeholder for the text ladder, brand instead of primary, -soft instead of -container.
  5. Timing: before the first export and before the manual is shared, or not at all this quarter.

Method

Bindings were read from every node’s paints and effects (paint.boundVariables.color, never the node-level list, which is not in paint order), on 22 Sep 2026 between 17:00 and 18:30. Node types VECTOR, BOOLEAN_OPERATION, LINE, ELLIPSE, STAR and POLYGON count as icons; TEXT as text; everything else as a container. Document mentions were counted as whole-word matches of the 47 names in the stripped HTML. Figma text mentions were counted the same way on the text nodes of the named frames. Raw scan data: scans.json and scans-agg.json in this session’s scratchpad.
